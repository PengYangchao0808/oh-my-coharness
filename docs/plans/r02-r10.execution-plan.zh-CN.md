## R02：逐请求预算闸门 + 跨进程预留（P0，先做）

**目标**：预算从"给建议"变成"阻止下一次真实请求"，且两个进程争最后一个名额时只有一个能发。

### 三个 ID 必须分开

| ID | 含义 | 归属 | 现有 |
|---|---|---|---|
| `executionAttemptId` | 一次任务执行（含多次模型调用） | `integration/execution-events.js` | 已有 |
| `modelRequestId` | 每一次真实发送尝试（含重试） | **新增**，`${taskId}#r${session}:${turn}:${step}` | 无 |
| `sourceEventId` | 返回事件身份，用于入账去重 | `usage-ledger` 的 `(backend, session, seq)` | 已有 |

**禁止**用 `executionAttemptId` 做所有请求共用的预留键——重试会共用一格。

### 落点与步骤

1. **新增 `integration/request-gate.js`**
   - 持久化文件 `${stateRoot}/budget/<parent>.json`，由 `withFileLockSync()`（`integration/file-lock.js`）保护；
   - `reserve({parentId, taskId, modelRequestId, maxCalls, maxUsd})`：**锁内**重读 ledger 已结算数 + 预留文件，判断 `booked + inflight + 1 > maxCalls` 或 `usd >= maxUsd`，允许才写预留并返回 `{allowed:true, reservation}`；
   - `settle({parentId, modelRequestId, outcome})`：`booked`（有 usage）/`unknown`（发送了但结果不明）/`refused`（未发送）三种终态；`unknown` **不退名额**，只在恢复对账时人工/宿主收据确认；
   - `reconcile({parentId})`：重启时把"预留但不是本进程"的条目转为 `unknown`，保留在文件里（不静默清零）。
2. **原生闸门接在 `agent/pre-step`，计数接在 `agent/request`**
   - `agent/pre-step` 是 WP00 已验证能拒绝一步、从而**阻止发送**的水位（`capabilities.json` `gate:pre-step-waterfall`）；
   - `agent/request` 拿到真实往返（含 retry 重入）→ 生成 `modelRequestId` 并留痕；
   - 拒绝时返回 `{kind:'reject'}` 携带 `OMC/BUDGET-STOP: ...`，并把 checkpoint 写入预留文件（`action:'stop-partial'`）。
   - `integration/budget.js` 的 `checkpoint()` 保留为判定函数，`reserveAttempt()` 的内存 Map 降级为**同进程快速路径**，不再作为唯一权威。
3. **停止语义**：达到上限 → 持久化 checkpoint（`reasons`、`coverage`、`unknownCost`）→ 拒绝下一次 pre-step → **执行状态保持 running/unknown，绝不写 completed**；已在运行的工具不强行砍断（按宿主契约）；父任务总预算与子任务配额显式区分（`maxCalls` 记父级，`perTaskCalls` 记单任务）。
4. **外部/直接路径的边界**：`src/provider.js` `start()`（约 line 110）在 spawn 前过闸，`src/dispatch.js` `dispatchTasks()`（约 line 434）在批分发前过闸；返回体标注 `hard:true|false`——外部 CLI 内部每一轮**不可控**，只能承诺 dispatch 之间。
5. **跨进程证据**：仿 `.ops/lease-contender.mjs` 新增 `test/fixtures/budget-contender.mjs`，两个真实子进程读同一份预留文件、在同一参数下各尝试一次；断言"恰好一个 allowed、另一个 `BUDGET-EXHAUSTED`、预留文件里只有 1 条"。受限沙箱下用文件 + 退出码通信，不依赖管道。

### 验收

- 两个独立进程争最后一格：恰好 1 个成功（**真实双进程**，不是进程内 Map）；
- 重试计数：一次执行内 2 次发送 = 2 次预留、2 条 ledger；
- 拒绝后没有任何适配器发送（探针里 adapter `dispatch` 计数不增）；
- 取消/重启不丢记录：预留转 `unknown`、checkpoint 仍在；
- 外部路径只标 `hard:false`，不被写成硬上限。

**验证**：`node test/integration/budget-runtime.test.mjs`、`node test/integration/wp06-budget.test.mjs`、`node scripts/native-bridge-live-check.mjs`（扩展一个"到额后下一次 pre-step 被拒"判定）。

**证据**：`docs/evidence/alpha.2/practice-r02-budget.json`。工作量：约 2–3 轮。

## R03：原生角色 × 工作包 × 消息 × 验收闭环（P0，依赖 R01/R02）

**目标**：原生 Explorer → Fixer → 独立验收走通；外部 Codex → 原生 Fixer 走通；失败可释放、可恢复。

### 落点与步骤

1. **派发即绑定**：`src/index.js` 的角色工具入口 + `vendor/omd/npm-package/preset/roles.js` 的 `patchedContext` 处，在激活前调用 R01 `native.bind({sessionId, parentId, nodeId, role, route})`；`integration/managed-execution.js` 增加原生分支（现在只有外部 dispatch）。
2. **首请求前注入**：原生 child 的第一条任务文本由**角色工具边界**拼装（宿主已把工具包装过），把 `mailbox.pendingInjections()` 的内容写进去并 `mailbox.recordInjection({attemptId})`；`injection` 记录先落地再返回，崩溃重试不重复注入。`queued/delivered/consumed` 三态不可混用。
3. **激活顺序固定**：`解析实际 cwd/最终策略 → 校验工作包(fitWorkPacket) → graph.claim → 预算预留(R02) → 持久化待注入上下文 → 激活 → 事件 → 执行结算 → 独立验收 → 解锁后继/释放`。
4. **结算与验收分离**：执行状态来自 R01 的 `turn/end`；验收只来自 `graph.complete(evidence)`。**后台启动返回 id 不算结算**，只算 `running`；旧 attempt 的验收证据不能带到新要求。
5. **批次契约**：宿主 `subagent_*` 一次只产出一个 child → managed 节点收到 `tasks.length > 1` 时**显式拒绝**（`OMC/MANAGED-BATCH`），不许用第一个结果代表全部。
6. **单 writer**：`graph.claim` 的 scope 约束在手写路径上生效；同一工作树先坚持"一个活动 writer"，读可并行。scope claim 是协作约束，**不替代**文件权限。

### 验收

- 原生 Explorer → Fixer + 独立验收各一次（真实 child，非 mock）；
- 激活失败 → claim 释放、可重试；重复结算幂等；
- 消息注入中断后重试不重复注入；
- 取消 → 节点 `failed/cancelled`，后继不解锁；
- 外部 Codex → 原生 Fixer 混链一次。

**验证**：`test/integration/managed-native.test.mjs`（新）、`wp05-managed`、`graph`、`mailbox`、宿主探针扩展。**证据**：`practice-r03-managed-native.json`。工作量：约 3 轮。

## R04：可轮换负责人 + 会话选择器（P1，依赖 R03）

**目标**：能解释"为什么续接/排队/压缩/重开"，且续接率**不是**优化目标。

### 落点与新增

- `integration/worker-registry.js`：逻辑 worker（project/module/role/实际模型/端点/权限/workspace/来源基线/最后验收）与物理 child（childId/generation/健康/忙闲）分开；`workerKey` 用 (project, module, role, route, permission) 的稳定摘要，源码正常变化不改变 key。
- `integration/session-strategy.js`：规则表 → `resume | queue | compact | restart | new-packet`；每次决策写 `${stateRoot}/decisions/<parent>.jsonl`：**当时可见特征、可选动作、选择、实际动作、规则版本、理由、后续结果**。
- 拒绝复用的硬条件：模型/权限/工作区不匹配、失败原因不明、旧事实失效。
- **不伪造 compact**：宿主历史视图能力有限（A11 只允许减少自有回显），没有合法压缩接口时记录为 `restart`；现有 `integration/context-view.js` 只作用于 OMC 自有回显与产物。

### 验收

- 同模块后续修正 → resume；child 忙 → queue（不并行塞两个任务）；独立审查 → new-packet；
- 过期/模型变更 → 拒绝续接或排队；无压缩能力 → 回退 restart 并注明；
- 决策记录可回放解释；测试里**不出现**"续接率越高越好"的断言。

**验证**：`test/integration/session-strategy.test.mjs`（新）。**证据**：`practice-r04-selection.json`。工作量：约 2 轮。

## R08：三档真实实验（P1，依赖 R05–R07）

| 档位 | 规模 | 能得结论 | 不能得结论 |
|---|---|---|---|
| 链路冒烟 | 3 任务 × 3 策略 × 1 = 9 trial | 派发/collector/grader/费用对账是否通 | 策略优劣 |
| 开发筛选 | 12 × 3 × 2 = 72 trial | 明显浪费、失败、候选规则 | 质量无损、自动晋升 |
| 冻结确认 | ≥30 任务 × 每任务每组 ≥2 次 | 冻结候选是否值得推广 | 统计充分性 |

- 每档开跑前冻结总模型费用、单任务上限、并发、截止、停止规则；由运行器执行；**不允许从冒烟自动升级到大批付费实验**；
- A/B/C = 续接/按需缩减、新建/可靠交接、自适应规则；同任务同模型同验收同总预算，组内随机顺序，隔离写入；
- 报告：原始 trial、冻结 manifest、实际版本、总费用与优化费用、成功率/回归/截断、P50/P95、任务级比较、未知项；成本/成功任务含失败与优化成本（通过数为 0 时未定义，不输出 0）；
- 缓存：同 session、重试、恢复、新 child、启用协议分别对账；只能验身份而不能验发送头/真实费用时继续标 `partial`。

**证据**：`docs/evidence/alpha.2/session-strategies/report.json` + `RESULTS.zh-CN.md`。工作量：约 3–4 轮（含付费预算审批）。

## 顺序、闸门与并行度

```
R02 ──► R03 ──► R04 ──┐
 │        │           ├─► R06 ──► R07 ──► R08 ──► R09 ──► R10
 └────────┴──► R05 ───┘
```

- 只有 R02 能先开工；R03 依赖 R02 的闸门（否则 managed 路径的预算只是建议）。
- R05 可与 R06 并行（前者 UI/配置，后者导出器），但都要在 R08 前完成，否则实验报告无法解释真实运行。
- R06/R07 是 R08 的前置；R08 未完成不得进 R09。
- 每项结束必须：`node scripts/run-tests.mjs` 全绿 + `node scripts/check.mjs` 通过 + 该项证据 JSON + 重生成 `practice-baseline.json`。

## 跨项工程约束

1. 复用现有 stores（ledger / execution / graph / mailbox / artifacts / sessions），**不新建第二套任务状态机**。
2. 宿主事件只用 `session/event`、`agent/created`、`agent/disposed`、`agent/request`、`agent/pre-step`、`agent/request-error`；不读改写会话文件做实时控制。
3. 未知一律显式 `unknown`：缺 usage、缺费用、缺终态、缺覆盖，都不能填 0 或填 completed。
4. 每次改动同步 `vendor/omd/PATCHES.md`（涉及 vendor 时）；旧显式调用保持兼容，新能力按支持范围启用。
5. 证据分层（实现/测试/宿主探针/真实模型/Desktop/费用覆盖），任何一层未过不得汇总为通过。

## 已知禁区（本阶段不做或不承诺）

- 外部 CLI 内部逐请求硬上限（只能在 dispatch 之间控制）；
- 核心会话历史的合法压缩（无接口就不做，标 `restart`）；
- 原生多 writer 强制文件隔离（scope claim 是协作约束）；
- 通过 DOM 改写 DSH 自带子代理菜单；
- 把缓存命中率当作已完成优化（身份可用 ≠ 发送头可用 ≠ 真实费用下降）。
