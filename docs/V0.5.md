## 2. Handoff Contract

### 2.1 为什么不是“消息传递”

Agent 之间没有点对点通信。主控是唯一调度者；一次交接只传下一阶段真正需要的事实：

```
任务目标 · 工作区 · 已改文件 · 产物引用 · 验收条件 · 约束
```

不传完整对话，也不传另一个 Agent 的中间推理。

### 2.2 记录形状

```json
{
  "version": 1,
  "taskId": "task-m3k2-9f1c2a",
  "projectId": "proj-4a91c02e77",
  "laneId": "lane-oracle-proj-4a91c02e77",
  "role": "oracle",
  "workspace": { "path": "e:/repo", "revision": null },
  "context": {
    "summary": "builder finished the session router",
    "changedFiles": ["src/provider.js"],
    "artifactRefs": ["artifacts/task-m3k2.patch"]
  },
  "acceptance": ["Report evidence for every claim."],
  "constraints": { "readOnly": true, "maxReviewRounds": 1 }
}
```

- `taskId` 只标识一次委派。
- `projectId` 由工作区路径哈希得到，不暴露路径。
- `laneId` 默认是 `lane-<role>-<projectId>`；同一角色在同一项目的连续工作共享 Lane。
- `workspace.revision` 是可选的 git revision；当前版本不主动调用 git。
- 路径必须是工作区相对路径；`/abs`、`C:\abs`、`..` 在 `validateHandoff` 阶段被拒绝。

### 2.3 如何穿过边界

`buildExternalBrief()` 在 Brief 末尾追加一个机器标记：

```
<!-- omc-handoff:v1:<base64url-payload>.<hmac> -->
```

- HMAC 使用 Host 进程内的随机密钥。只有本进程构造的 Brief 才能被 Provider 信任。
- Provider 在启动 CLI 前剥离标记，CLI 永远不会看到它。
- 直接 `coharness({action:'dispatch'})` 的 prompt 没有签名标记，因此**不会续接任何角色会话**；手工复制/伪造标记会得到 `malformed`，只剥离、不信任。
- v0.4 的旧 Brief 只有 `Role:` 行，仍能解析出角色和 Lane，但不会启用 Session Resume。

### 2.4 最小交接原则

| 场景 | 传递 | 不传递 |
|---|---|---|
| Explorer → 主控 | 文件位置、符号、结论 | 完整搜索过程 |
| Oracle → 主控 | 方案、风险、证据 | 内部推理链 |
| Builder → Reviewer | diff、测试结果、决策 | 整个会话 |
| Reviewer → 原 Builder | 缺陷、文件位置、修复目标 | Reviewer 的完整对话 |
| Council 席位 | 各自独立回答 | 其他席位的原始对话 |

## 3. Native Session Registry

### 3.1 两个 ID 不能混用

| ID | 属于谁 | 生命周期 |
|---|---|---|
| DSH Child ID | 本次 DSH 子任务 | 这次运行 / 完成通知 |
| Native Session ID | 外部 CLI 自己的会话 | 跨多次 DSH 运行 |

每次 DSH 运行都有新的 Child ID；即使续接同一个 Native Session，也不会复用 Child ID。

### 3.2 存储

```
$DSH_HOME/oh-my-coharness-sessions.json
（默认 ~/.dsh/oh-my-coharness-sessions.json，可用 sessions.path 覆盖）
```

结构：

```json
{
  "schemaVersion": 1,
  "updatedAt": "2026-10-30T07:00:00.000Z",
  "sessions": {
    "<sha256(key)>": {
      "key": {
        "projectId": "proj-...",
        "laneId": "lane-...",
        "role": "oracle",
        "harness": "codex",
        "model": "gpt-5",
        "environment": "wsl:Ubuntu",
        "workspace": "e:/repo",
        "endpoint": "a1b2c3d4e5f6"
      },
      "native": { "sessionId": "thread-...", "format": "codex-jsonl" },
      "state": "idle",
      "createdAt": "...",
      "lastUsedAt": "...",
      "turns": 3,
      "usage": { "last": { "...": null }, "totals": { "...": null } },
      "lastTaskId": "task-...",
      "lastError": null
    }
  }
}
```

- 只存 opaque ID、会话键和用量；**不存 Prompt、对话、Token、密钥**。
- POSIX 下文件以 `0600` 创建；Windows 依赖用户目录 ACL。
- 原子写：同目录临时文件 → rename；Windows 下 rename 失败时退化为“删除再 rename”，但会保留损坏文件的 `.corrupt-*` 备份。
- 损坏的 JSON 不会让插件崩溃：`stats().loadError` 可见，首次写入前把原文件移到备份。

### 3.3 会话键

任一字段不同都不得复用：

```
projectId · laneId · role · harness · model · environment · workspace · endpoint
```

`endpoint` 是端点 + envFile mtime 的哈希，不包含凭据。这样：

- GLM 与 Claude 共用 `claude` 二进制也不会串用；
- 更换模型、WSL 发行版、工作区或端点后默认新开会话；
- envFile 内 token 轮换（mtime 变化）也会新开。

**显式 `cwd` 是启用 Resume 的前提。** 没有 `cwd` 时外部 CLI 继承 Host 进程目录，那不是用户项目；这种调用一律不读写会话引用。

### 3.4 状态机与 lease

```
(no record) → running → idle
                    ↘ failed
                    ↘ unconfirmed
idle → running（续接）
```

- **单写者**：同一个 key 同时最多一个 lease。第二个调用排队；超过 `lockTimeoutMs` 报 `OMC/SESSION-BUSY`。
- `failed` / `unconfirmed` / `invalidated` 不会自动续接，避免把一次失败当成可复用的上下文。
- `turns >= maxTurns` 或空闲超过 `idleTtlMs` 后不再续接。
- `require-resume`：没有可续接会话时在启动 CLI 前直接失败。
- 用户可用 `/coharness sessions --clear` 清空 OMC 引用；**不删除 CLI 原生历史**。

### 3.5 恢复失败的判定

CLI 退出码 0 不等于恢复成功。尤其是 Kimi 在 session id 不存在时可能自动新建会话。

因此：

- 续接后必须从 JSON 输出里读到 Native Session ID；
- 读不到时标记 `unconfirmed`，不把旧 ID 当作已确认；
- 只有 `idle` 且身份确认的记录才允许下一次续接。

## 4. CLI 适配器

| Harness | 新会话捕获 | 续接 argv | confidence | 默认 |
|---|---|---|---|---|
| codex | `exec --json`，读 `thread.started.thread_id` | `exec resume <id> ...` | verified | ✅ |
| claude | `--output-format json`，读 `session_id` | `--resume <id>` | documented | ✅ |
| kimi | `--output-format json`（形态未验证） | `--session <id>` | unverified | 需 `allowUnverified` |
| opencode | `--format json`（形态未验证） | `run --session <id>` | unverified | 需 `allowUnverified` |
| gemini | `--output-format json`（形态未验证） | `--resume <id>` | unverified | 需 `allowUnverified` |
| glm | 同 claude，Z.ai 端点 | 同 claude | unverified | 需 `allowUnverified` |
| antigravity | 未实现 | 未验证 | — | ❌ |

`confidence` 的含义：

- `verified`：本机真实两轮跑通（Codex，2026-10-30；续接轮沿用原会话的只读沙箱并复用缓存输入）。
- `documented`：命令形态有官方文档依据，但尚未做真实两轮验收。
- `unverified`：argv/JSON 形态未确认，必须显式 `allowUnverified: true`。

Codex 已完成从 `documented` 到 `verified` 的升级；Claude 仍需同样的两轮验收，Kimi / OpenCode / Gemini / GLM 逐个验证后再默认开启。

**`codex exec resume` 没有 `-s` 参数**：续接轮沿用会话创建时记录的沙箱策略。因此永远不要续接一个可写会话，只读会话才能安全复用。

### 4.1 输出解析

- `codex-jsonl`：逐行 JSON 事件；取最后一个 `item.completed` 的 `agent_message`，取 `thread.started.thread_id`，取 `turn.completed.usage`。
- `claude-json`：取 `result`、`session_id`、`usage`、`total_cost_usd`。
- `generic-json`：对 Kimi / OpenCode / Gemini 的常见键做宽松提取。
- 解析失败时回退到原始 stdout；不会因为解析器不认识格式就丢掉 CLI 的回答。
- Usage 缺失时字段为 `null`，**绝不写成 0**。

### 4.2 Harness Adapter 契约

`src/adapters.js` 把每个外部 Harness 视为一个执行后端，而不是“一条 CLI 命令”：

```
probe/capabilities → start | resume → status → collect → cancel
```

Provider 与 direct dispatch 共用同一份适配器，所以新增传输不会长出第二套任务状态机。`harnesses.<id>.adapter` 选的是协议（`cli | mcp | app-server`），与 `harnesses.<id>.transport`（native / WSL 进程位置）是两件事，不要混用。

目前只实现了 `cli`；`mcp` 与 `app-server` 会明确返回 `OMC/ADAPTER-UNSUPPORTED`，而不是悄悄降级成另一个后端。

## 5. 配置

```json
{
  "sessions": {
    "enabled": true,
    "path": "",
    "resumePolicy": "auto",
    "maxTurns": 24,
    "idleTtlMs": 604800000,
    "lockTimeoutMs": 120000,
    "allowUnverified": false,
    "captureUsage": true,
    "maxEntries": 200
  },
  "routing": {
    "enabled": false,
    "preset": "balanced",
    "roles": {},
    "allowPaidApi": false,
    "allowUnknownBilling": false,
    "limits": {
      "maxParallelExternal": 3,
      "maxOracleCallsPerTask": 1,
      "maxReviewRounds": 1
    }
  }
}
```

- `sessions.enabled=false`：不读不写 Registry，也不加 `--json`/`--resume`，行为回到 v0.4。
- `resumePolicy='new'`：仍采集用量，但每次新开。
- `routing` 默认关闭：关闭时只在 `/coharness status` 给建议；开启后，角色没有显式 `role.execution` 时策略才接管路由（仅限可外部执行的角色）。显式 `role.execution` 永远优先。
- `allowPaidApi` / `allowUnknownBilling` 默认 `false`：自动路由只使用 `harnesses.<id>.billing` 为 `subscription` 的线路；`api` 与 `unknown` 必须显式放行，单条偏好可用 `authorizeBilling: true` 覆盖。**未知不等于免费。**

## 6. 性能与度量

本批已实现的实际优化：

1. **Transport 计划缓存（60s）**：避免每个角色轮次都执行 `wsl.exe -l -q` + 登录 shell 查找。失败不缓存，安装新 CLI 后下一次仍会重新探测。
2. **同 Lane 续接**：减少重复项目背景、已有决策和文件上下文的传输。
3. **稳定 Persona 前缀**：Brief 的角色段落顺序固定，便于服务商 Prompt Cache 命中。
4. **单 Lane 串行、跨 Lane 并行**：避免多个 Builder 同时改同一模块。
5. **Usage 采集**：为后续 `Cost per accepted task` 提供字段；当前只记录，不做自动模型评分。

建议的基准（尚未跑）：

| Benchmark | 对照 | 指标 |
|---|---|---|
| Session Reuse | 新会话 vs 同 Lane 续接 | 耗时、缓存 Tokens、总用量 |
| GLM Coding | Native vs 外部 Harness | 测试通过率、返工轮次 |
| Multi-Agent Review | 单 Reviewer vs Council | 有效缺陷数、成本 |
| Frontend | Kimi vs Gemini/Antigravity | UI 验收通过率、修复次数 |

保留 `usage unavailable`：某个 CLI 不返回 Token/费用时显示“不可得”，不能记为零成本。

## 7. 安全边界

- 外部 CLI 仍运行在 DSH sandbox/approval 之外；`enforced` 只读来自 CLI 自己的沙箱，`advisory` 只是约定。
- `omc:*` provider 仍固定只读；v0.5 没有新增可写 provider。
- Handoff 只接受工作区相对路径；签名防止直接 dispatch 伪造会话身份。
- Session Registry 是敏感元数据：不存 Prompt/Token/对话；日志只显示掩码 ID。
- 不复用跨项目会话；缓存收益不得高于上下文隔离和正确性。
- 清除 OMC 引用不等于删除 CLI 历史。
