# OMC 0.5.0-alpha.2 验收方案

日期：2026-11-03。状态：**待执行**。配套 [版本方案](V0.5-ALPHA2-PLAN.zh-CN.md) 与 [backlog](plans/v0.5.0-alpha.2.backlog.json)。本文是验收规格，不是测试结果。

## 1. 证据规范

每份结果记录：用例 ID、日期、代码版本和工作树指纹、DSH/CLI 版本、profile/执行路径、前置条件、检查过程、期望、实际结果、产物引用、模型调用数和费用覆盖情况。

结果为 passed / failed / blocked / not-run；blocked 与 not-run 不能计作通过。模拟回归、宿主装载、真实模型链路和 Desktop 点击分别标记，不能互相替代。

使用隔离测试工作区与 profile。离线回放不触发模型；真实链路和对照评估使用事先明确的模型、任务数量及预算，单独记录实际消耗。用量证据不包含授权头、密钥或原始内部推理文本。

## 3. 发布闸门

| 闸门 | 包含用例 | 通过含义 |
|---|---|---|
| G0 正确性与能力 | A00–A04 | 明确能力边界；已知三类缺口修复 |
| G1 状态与证据 | A05–A10 | 身份、用量、结果、工作包与产物可信 |
| G2 受控协作 | A11–A20 | 支持路径上的上下文、执行图、消息和检查点闭环 |
| G3 兼容与产品 | A21–A25、A29 | 声明支持的缓存路径、设置、安装、Desktop 和回退验证 |
| G4 效率与质量报告 | A26–A28 | 有可追溯对照结果；质量问题不能被节省指标掩盖 |

发布“受控协作可用”必须 G0–G3 通过，且至少原生与 Codex 外部路径覆盖。G4 的试验及报告也必须完成，但 A28 的收益数字是目标，不是必须通过挑样本实现的硬门槛。未达收益目标则保持 observe 默认，不宣传量化收益。

缺宿主能力而无法满足 G2 时不得将其记为 passed；可继续开发或仅发布清楚限定范围的观察版本，版本说明必须重写为实际交付范围。

## 4. 对照实验设计

先用历史日志离线验证四桶汇总、重复事件、上下文视图大小和检查点判定；这些检查不产生新的模型费用，也不证明成功率。

真实试验先选 10–15 个固定任务，覆盖：局部修复、跨文件接口、状态/并发、独立模块。每种方案至少重复两次，作为小规模筛选：

- A：当前流程，固定起始模型和可用工具。
- B：A + 工作包/产物/上下文管理。
- C：B + managed 调度/检查点/无进展治理。
- 选取部分任务另跑单负责人基线，确认团队本身是否值得。

验收要求在跑实验前冻结，包含固定外部测试及必要人工/独立复核。模型新写的测试只能补充。所有方案使用相同起始工作树、模型、依赖和任务总预算；辅助请求和重试不得从费用统计中剔除。

费用记录实际账单或可追溯价格估算，二者分开；未知项单列。费用/通过任务 = 所有尝试费用 ÷ 通过任务数；无任务通过时该指标为未定义，不输出 0。

墙钟时间从接收任务到最终验收，报告 P50/P95 及失败超时处理规则；小样本 P95 不稳定，必须同时展示样本数与单次分布。速度不能仅在成功子集中比较，还要展示全体截止时间、失败率与预算截断率，避免提前放弃被算成提速。

对输入 token、调用次数和费用逐项报告，不合并成一个无定义的“效率分数”。上下文缩减的冷启动开销计入总量。争取达到试验目标之后仍需扩大样本、重复次数并报告区间，再决定是否扩大 balanced 的默认范围。

## 5. 版本证据清单

WP09 产出版本目录，建议包含：能力矩阵、功能用例结果、usage 对账、Desktop 录屏/截图与收据、tarball 与隔离安装结果、固定任务清单、逐次实验指标、汇总报告和已知限制。

每项结论指向实际文件；本文件与 backlog 中的 planned 状态不能被当成验收证据。版本号在完成相关检查之后统一更新，不提前将方案文档中的 alpha.2 当作已安装版本。
