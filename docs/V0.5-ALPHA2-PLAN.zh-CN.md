## 1. 版本决定与目标

2026-11-03 补充：[三策略监控、反馈与自主优化子方案](FEEDBACK-EVOLUTION.zh-CN.md) 已增加离线评估工具及独立 F00–F05 工作包。它扩展 WP09 的实验基础，不将已有 WP 状态重置，也不代表真实三组对照或在线自主进化已通过。固定负责人、续接、压缩与重开均作为待验证策略，续接率不作为晋升目标。

下一版采用 `0.5.0-alpha.2`，主题为“减少重复处理、控制长循环、接通协作闭环”。先建立可核算的效率基础，之后再扩大自动组队和模型路由。

目标有三个：

1. **减少 token 和实际成本**：缩小重复上下文，按工作包复用事实与产物，控制无效重试和长循环。
2. **缩短最终完成时间**：减少重复侦察和状态轮询；有依赖的工作按顺序推进，独立工作才并行。
3. **提高任务成功率**：修复错误结算与策略绕过，统一执行结果和业务验收，针对关键风险触发独立审查。

已有事实：两批已结算子代理输入缓存命中约 95%，仍累计产生 1,022 个有用量的模型响应。WP2 为 162 次，最大单次输入 341,803 token。历史数据只解释症状，不能替代新旧版本的受控比较。

### 版本边界

| 范围 | alpha.2 决定 |
|---|---|
| 正确性、真实模型和用量 | 必须交付 |
| 小工作包、产物引用、受控上下文 | 必须交付最小闭环；历史视图重写需能力验证 |
| 预算检查点、无进展检测 | 必须提供真实能力标识；支持的路径交付受控模式 |
| graph 与实际执行绑定、mailbox 下一轮注入 | 必须交付 managed 路径 |
| 团队规模 | 初始受控模式最多 2 个活动 worker、1 个活动 writer；主控另计，费用统一计入 |
| 原生并行写入、自动合并 | 延后；已有外部 worktree 保持显式验证和合并 |
| 自动选模型、自动扩大人数 | 延后到 alpha.3，alpha.2 保留显式路由和受限升级 |
| Observer、全面 AST/LSP、自由辩论团队 | 延后，不挤占本版核心链路 |
| 跨供应商 KV 共享、GPU 缓存控制 | 不属于本版托管 API 插件范围 |

alpha.2 不要求 OMO-SLIM 全功能等价；对应差异继续保留在独立报告，避免将效率发布误写为完整复刻完成。

## 2. 发布模式与默认行为

拟增加统一 `efficiency` 配置，置于现有单插件配置文档中；Host 校验、设置卡 schema 与持久化仍共用一套来源。

| 模式 | 行为 |
|---|---|
| `off` | 关闭本版可选效率功能；正确性修复始终生效 |
| `observe`（升级默认） | 记录调用、实际模型、用量和进展提示；不自动改变旧任务、模型或上下文 |
| `balanced`（新会话显式启用） | 使用工作包、产物引用、检查点、managed 工作图及下一轮消息注入 |

启用 balanced 前执行能力检查。不能履行的受控能力返回具体原因，不静默降级后继续标记 balanced。可以切回 observe，并明确显示哪些能力未启用。

本版不设置一个含糊的“strict 全能模式”：逐请求拦截得到验证后，才能单独提供调用次数上限；费用只能按已知价格与真实 usage 做预算提示或保守预留，不能承诺供应商账单绝不超额。

拟议默认值如下，**这些字段尚未实现，不应直接粘贴到当前配置**：

```json
{
  "efficiency": {
    "mode": "observe",
    "team": { "maxActiveWorkers": 2, "maxActiveWriters": 1 },
    "checkpoints": {
      "explorerSteps": 16,
      "fixerSteps": 40,
      "oracleSteps": 12,
      "explorerInputTokens": 60000,
      "fixerInputTokens": 120000
    },
    "context": { "maxToolTextChars": 12000, "packetMaxChars": 8000 },
    "budget": { "maxCalls": null, "maxUsd": null },
    "progress": { "repeatWindow": 6, "repeatThreshold": 3 }
  }
}
```

数值是试验起点；`steps` 指有模型响应的执行步，`maxCalls` 则统计真实请求尝试，包括重试，两者不可混用。主控、worker、审查和总结请求都归入父任务预算。单次输出 `maxTokens` 仍是模型参数，不作为任务总预算。

## 3. 必须先核实的宿主能力（WP00）

已知 `agent/request` 可以改写角色请求配置，`agent/created` 可以挂载角色组合；**尚不能由此推断它们覆盖了每一次模型循环**。

开发前用当前实际安装的 DSH 构造隔离探针，确认以下能力及其时序：

| 能力 | 要验证的事实 | 未满足时的边界 |
|---|---|---|
| 每步 usage | 请求与终态事件可关联，可重放，缓存桶含义明确 | 标记部分覆盖；不显示完整预算已接管 |
| 下一次调用闸门 | 在真实发送前执行，重试也覆盖，并发可原子预留名额 | 不提供精确 maxCalls 上限；balanced 发布范围须收缩或等待修复 |
| 结果文本视图 | 可在进入后续上下文前替换展示视图，同时保留原始证据 | 先限制 OMC 自有回显和使用产物引用；不改写宿主原始日志 |
| 历史视图变换 | 可重放、可恢复，不改变原始会话事实与权限 | 旧工具输出遮蔽保留实验状态，不作为强制功能 |
| 子任务结算 | 完成、失败、取消及恢复事件的顺序和身份可验证 | 保留 unknown，禁止用最新消息推定完成 |
| 动态会话头 | 当前 adapter 的发送边界能取得实际 sessionId | 通过宿主/adapter 改动解决；不向安装 ASAR 注入临时猴子补丁 |

交付 `capabilities` 证据矩阵，按 native、external provider、direct 分别记录 supported / partial / unsupported。升级和模型切换后允许重新探测。至少有已验证的 native 路径和 Codex external 路径通过本版最小闭环，才能将 alpha.2 称为“受控协作可用”。否则可以继续开发或交付观察版本，但不得标记该发布门槛通过。

## 4. 核心契约

### 4.1 身份、生命周期与验收分开

沿用现有 `parentId/taskId/childId/lane`，补充稳定 `attemptId`。一次失败后的重试或换模型是新 attempt，仍属于同一 task；避免重试被统计成新的独立需求。

- 执行状态沿用现有 running/completed/failed/cancelled/unknown，不在兼容字段里偷偷改变其含义。
- 新增 `acceptanceState: pending | passed | failed | unknown`，表达工作交付是否通过验收。
- 对开发任务，只有执行完成且当前集成版本的验收 passed，主控才能宣称交付完成。纯咨询任务使用适合其类型的证据要求。
- `cancelRequested` 不等于 cancelled；收到取消请求但进程仍在运行时继续保留真实状态。
- RoleResult 新增字段保持可空；无证据的模型、费用或产物不能推测填入。

### 4.2 用量台账

每条事件至少记录：父任务、task、attempt、执行后端、来源事件 ID/序号、请求 ID（若有）、实际 provider/model/effort、四个互斥 token 桶、费用来源/价格版本、时间和覆盖情况。

入账原则：

1. 以真实发送/返回路径为准，区分初始配置、实际请求路由和后续切换。修复创建描述仍显示旧模型的问题；若宿主描述无法更新，界面明确显示“初始”与“实际”。
2. 按来源 + session + 事件标识幂等写入；重启回放不重复计费。子任务汇总不再作为父任务自己的调用重复入账。
3. 输出中包含的 reasoning 不再额外相加；缓存写入为零不解释成服务器没有缓存。
4. 缺失 usage、价格或网关 allowance 时为 unknown/partial。不能用零填补；历史价格缺失不能用今天价格冒充账单。
5. 请求发送失败、超时和取消均有 attempt 记录；无法获知供应商实际扣费时保留未知成本。

新状态按现有 profile 分区存储，采用版本化记录和现有跨进程锁。新目录与旧 sessions/tasks 共存，避免一次性重写旧会话。台账只存必要元数据，不存凭证、完整提示词或内部推理文本。

### 4.3 WorkPacket 与 Artifact

WorkPacket 包含目标、验收、读取定位、写入责任、工作基线、已验证事实/决策、未决问题、产物引用和预算引用。对 native 与 external 统一语义；外部 Handoff 签名、CLI session key 和权限约束继续保留。

事实必须包含 `sourceRef + sourceDigest + observedAt`；基线同时包含 commit 与工作树内容指纹，支持未提交修改和非 Git 工作区。摘要只辅助理解，原始证据可按需取回。

Artifact 最小功能：受控存储、稳定 ID、内容摘要、来源 task/attempt、内容 hash、读取范围、受限展开。路径必须经过工作区/产物根目录校验；缺失或失效返回具体错误，不静默给出旧内容。

对工作包限额不能直接截断关键约束：超限时将可外置材料转为引用，仍超限则拒绝并要求缩小工作包。预算、验收和权限条件不得被自动丢掉。

### 4.4 上下文与本地缓存

优先处理新进入上下文的长工具文本：返回短摘要、退出码及完整产物引用。原始工具调用与证据继续持久保留；默认阶段内保持稳定前缀，阶段边界再进行视图缩减。

本版只缓存可证明无副作用的检索结果。key 包含工作区身份、相关内容指纹、工具及版本、参数；读取失败或无法判断失效条件即视为 miss。测试结果先作为可复用证据存储，**不自动跳过最终验收测试**。构建缓存和跨机器测试缓存延后，避免不完整 key 造成假通过。

历史视图缩减需 WP00 验证通过后才实现，并检查 tool-call/result 配对与重放。既不删除原始日志，也不从其他进程直接编辑 DSH 会话文件。

### 4.5 预算与无进展检测

程序计数，不为更新预算新增模型调用。检查点动作限定为：继续、缩小范围、外置/压缩上下文、切换假设、提出一次受限升级、等待外部条件、停止并报告部分结果。

无进展信号组合使用：调用参数指纹、代码/产物变化、失败测试集合、已验证事实变化。连续三次相似调用只是信号，不单独判定失败；明确需要轮询的异步工作与有代码变化后的重试不能被误杀。

调用上限在可验证的请求闸门处原子预留，包含并发与重试。取消名额与超时释放必须有终态/发送证据；不能把已经发出的请求退回为未使用。费用预算受 usage 延迟与在途请求影响，界面显示已结算、在途和未知部分。

停止先形成持久检查点，并在安全的调用边界终止后续请求。强制取消使用宿主真实中断契约；不能因预算耗尽把任务写成 completed。父会话关闭后依旧保留未结算任务，恢复时先对账。

模型升级最多每节点一次，且受总预算、显式路由、可用性和既有付费授权约束。权限错误、错误路径、配额和工具故障按类别处理；不统一升级模型。本版不自动扩容团队。

## 5. 协作执行闭环

新增 managed 执行路径：`校验 WorkPacket → 应用最终策略 → graph claim → 预留并发/预算 → 激活 → 接收事件 → 记录结果 → 验收 → settle/release`。激活失败、超时与进程崩溃也必须释放或恢复 claim，事件处理可幂等重放。

先提供明确的 `taskId/nodeId` 绑定。balanced 会话中的 OMC 角色/dispatch 必须经过 managed 入口；旧的显式调用保留兼容，但标明 unmanaged，不计入“全部写入已受 graph 管理”的承诺。用户或外部程序自行启动的 CLI 不在该保证范围内。

工作图状态与执行状态不混用：worker 执行完毕不自动意味着依赖已验收；只有验收通过的节点才能解锁要求通过的后继。

### 消息与复用

- 原生投递、外部 queued 和下一轮消费显示不同状态，不将 queued 说成“已影响运行”。
- mailbox 消息按 ID 有序注入同一 task/lane 的下一次合法续派；写入可重放的接收上下文后确认消费。崩溃重试依靠注入键幂等去重。
- `reuse` 原有 inspect 行为保持；增加显式执行选项时，重新检查策略、工作区、模型与 session key，不能仅凭旧任务记录越过当前授权。
- 指向已结算任务的改动需求创建新的 attempt/后续节点，旧验收证据不自动延用。

### 写入与验收

本版 managed 同一工作树最多一个活动 writer，独立读任务可并行。文件范围 claim 是协作契约，不能代替宿主文件权限；native 并行隔离写留到 alpha.3。

不同文件仍可能依赖同一接口。共享接口先由单一节点产出契约，下游依赖它。高风险变更触发一次独立审查；审查结果按证据和可复现实验裁决，不按赞成票数。

## 6. 缓存亲和方案

区分两层：客户端复用事实/产物，供应商复用同模型的提示前缀。alpha.2 不宣称能导出 KV 或跨 provider/model 共享 KV。

通过受支持的 adapter 接口传递稳定会话身份：同一 child 的续接、重试保持身份，新 child 使用独立身份；辅助总结/标题请求按宿主实际会话归属传递。对 Go 验证动态 `x-opencode-session` 或被认可的等价会话头，不使用所有会话共用的固定值。

请求头探针只记录名称和会话值的相等/不同关系，不记录授权头。测试覆盖普通对话、子任务、重试、恢复及实际启用的协议。若当前适配器缺接口，交付兼容性说明与可审阅的适配改动，未通过前保持 partial；本版不得为此直接修改用户安装的 ASAR。

验收同时看真实返回的缓存桶和最终成本，不能仅依据“请求里有 header”判为优化成功。`cacheRetention: long` 不作为 DeepSeek 的通用开关。缓存命中率可以因上下文缩减暂时下降，最终选择看成本、速度与质量。

## 8. 验收与发布门槛

详细用例见 [验收方案](ACCEPTANCE-V0.5-ALPHA2.zh-CN.md)。本版采用四层证据：纯契约/回归、无模型宿主探针、小规模真实链路、受控新旧对照。

### 必须满足

- 已知策略绕过、无效结构化输出假成功、快照误报分别有真实组合回归并修复。
- 台账对原生及外部样本对账；重启、重复事件、切模型不重复入账；未知成本可见。
- managed 原生 + Codex 外部链路完成工作包、消息消费、结果、验收与预算检查点；功能覆盖如实显示。
- 相同工作树 writer 冲突被阻止；claim 在激活失败和恢复后可正确处理。
- 预算耗尽不误报完成，未结算取消保持真实状态；缺能力时拒绝不支持的受控保证。
- 现有测试、必要新回归、自检、真正的 tarball 隔离安装和 Desktop 验收通过；旧 268 项通过只作为历史基线，不当作本版结果。
- 非 Codex CLI 逐项标记 verified/unverified，不因共享代码路径扩大兼容性承诺。

### 效率目标与质量约束

试验性目标：对预先选定的长循环任务，争取调用次数与累计输入减少 25%，验收通过任务的平均费用减少 20%，P50 最终完成时间减少 15%。**这些是待检验目标，不是预测或既成收益，也不是通过删掉必要验证来达到的指标。**

质量门槛：固定验收集无新增关键回归、无错误完成声明；记录每种方案的成功率、预算截断率与失败类别。小试验不能证明统计意义上的质量无损，扩大 balanced 默认范围之前需增加重复次数与区间估计。若目标未达到，保留 observe 默认并公布结果，不发布量化提效宣传。

## 9. 配置、迁移与回退

升级默认 observe；不修改现有角色模型、付费授权和运行中的 child。新会话启用 balanced 时捕获不可变启动基线，后续实际请求路由另行记录。手动 snapshot 继续保留，但标为 manual，不能伪装启动快照。

项目可收紧最终请求权限、预算与并发，不能通过单次 mode/timeout、fallback 或省略 cwd 绕过；在解析真实 cwd 后应用限制。read-only、worktree 和 in-place 按允许集合处理，避免将两种写模式视作简单大小关系。损坏或不可读取的已存在项目策略阻止有副作用的派发并报告原因，不默认为空策略。

旧 task/graph/session 数据兼容读取；新增字段缺失时为 unknown。新写入用独立版本记录，迁移不删除 CLI 历史或用户文件。配置回退到 observe/off 后保留诊断数据与旧操作入口；进行中的 managed 任务先结算或明确交接，不能直接丢失 claim。

版本号只在 WP09 验收后统一修改 package、自检中的固定版本断言及相关清单；此前不提前 bump。发布操作单独执行，本方案不包含自动上传或市场提交。

## 10. 决策结论

本版先让成本、任务状态、消息消费与验收可信，再用可恢复上下文和程序化检查点减少无效工作。自动扩大团队、复杂模型选举及原生并行写入留待这些闭环稳定后实现。

开发入口明确为 **WP00 → WP01 → WP02/WP03**。该顺序是实施依据；功能完成状态以配套验收记录为准。
